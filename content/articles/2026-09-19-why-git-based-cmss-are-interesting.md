# Why Git-Based CMSs Are Interesting

This is an experiment with Pages CMS.

The goal isn't to build a production CMS.

The goal is to understand what happens when a friendly editorial interface sits on top of Git, Markdown, structured metadata, and a static-site build pipeline.

## The experiment

We are testing:

- Structured content

- Media

- Markdown

- Git workflows

- References

- Reusable components

- Blocks

- Automated publishing

The interesting question is:

> How far can a Git-based CMS go before you actually need a traditional database-backed CMS?

## What I'm learning

Pages CMS feels simple on the surface, but its configuration can describe surprisingly sophisticated content models.

This repository is where I'm going to push it to its limits.
